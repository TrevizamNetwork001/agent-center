# Automatic compatible Agent updates — 0.5.8

The operator requested clicking Atualizar Agent to show the update flow directly, then download/install after one confirmation and return to the Agent page. The link now opens the in-page update section. Manual setup is a separate, explicitly named one-time preparation action for older companions. Existing 0.5.6 cannot acquire download code through its existing pre-staged-only protocol, so it requires one local installer repair. Do not claim a remote upgrade has happened before the host reports it.

0.5.8 companion stages a missing release during an authorized update precheck only. It uses the locally configured HTTPS Central origin and a fixed /downloads/agent/releases/<sha256>.pyz path. It ignores operation-supplied URLs and paths, uses verified TLS, no redirects, no proxy, no bearer token on public downloads, a bounded body and timeout, exact digest validation, archive checks and unprivileged expected-version self-check before adding a durable root-owned catalog entry. Downloads never swap the live runtime. Apply/rollback cannot fetch absent candidates. Root ownership/path checks and the shared maintenance lock are retained.

The companion advertises release_download_protocol=1. UI readiness follows that stable protocol plus a current poll, rather than exact equality with the latest installer version. A stale poll produces a connection message rather than asking to reinstall a capable companion. Existing known helper versions remain accepted. Initial authorizer, tenant policy, precheck evidence, backup, postcheck and rollback behavior remain enforced. New safe errors are release_download_failed and invalid_release. DNS fix and AmbientCapabilities=CAP_SETUID are included.

Validation: 69 Python tests including consecutive release staging, tampered content, unsafe paths, no-token fixed-origin downloads, no redirects, bounded data, unsupported phases, and failed self-check without catalog authorization. 13 installer/repair tests; 49 Laravel tests / 533 assertions on a separate test database with migration up/down, including stable download protocol, inline update link, one-time setup, stale poll and tenant boundaries. PHP/Python lint. Previous automatic return JavaScript is unchanged.

Release/runtime artifacts are content addressed. The public download allowlist adds the exact 0.5.8 kit/checksum and digest-only .pyz path; other administrative access rules stay in place. Deployment backs up source, artifacts, running web files, compose and vhost; applies files atomically under their directory owner; validates/reloads Nginx and clears compiled views without recreating the web container. A persistent image contains the same web files. Rollback restores the snapshot, compose, web files and vhost then validates/reloads Nginx and clears views. No tenant data migration or real maintenance operation is created by publication.

After publishing: verify the real HTTPS download and expected-version self-check in an isolated temporary systemd service, with CAP_SETUID ambient and protection settings. The remote host still needs the one-time preparation, then confirmation in the panel. A later compatible runtime update needs only the panel; companion updates that add a new maintenance protocol may require a distinct preparation in future.
