# Cadastro sem digitar código

O operador solicitou explicitamente: executar o instalador geral, mostrar aguardando aceite no terminal, exibir a máquina no painel e concluir após aceitar. Solicitações sem tenant pertencem exclusivamente à administração da plataforma. O administrador seleciona o cliente e confirma a identidade antes de aceitar. Contas de tenants não listam, consultam nem aceitam essa fila.

API pública limitada a POST /api/v1/agent/bootstrap/request e /status, com rate limit de origem e de cadastro; status limitado por hash do recibo. O registro rejeita tenant_id e agent_id. Nenhum Agent ou credencial operacional é criado sem aceite. Solicitações ficam em namespace administrativo separado no cache existente por 30 minutos, com índice limitado a 1000 entradas e locks. O recibo de 256 bits é entregue só à máquina, armazenado como hash na Central; nunca aparece no painel. No host, fica em /var/lib/agent-center-bootstrap/request.json root:root 0600, diretório 0700.

Aceite autenticado com CSRF, autorização platform_admin e tenant ativo. Cria Agent/enrollment exclusivamente no tenant escolhido, com autorização prévia e auditoria. Código de uso único dura 15 minutos, é criptografado no cache e entregue exclusivamente ao portador do recibo. Não é exibido ao operador. O helper fornece o código ao instalador aprovado em terminal privado com echo desabilitado; nenhum segredo em URL, argumento, variável de ambiente ou saída. O enrollment e a emissão única de token permanecem nos endpoints existentes, com RLS. O runtime aprovado 0.5.3 e seu kit não mudam.

Instalador valida SHA do kit e do helper. Confere Linux/Debian/Python e kit antes de solicitar aceite. Caso a instalação anterior tenha parado no prompt de código, aceita retomada somente sem identidade/recibo de enrollment, com runtime/helper e configuração conferidos. Não sobrescreve identidade existente. Instalações conflitantes ou falhas preservam dados e exigem revisão. Aprovação termina automaticamente; helper original confirma heartbeat e poll na retomada. Não foi instalado Agent nesta VPS Central.

Publicação sem migrations, grants, mudança em RLS ou serviços de outros projetos. Imagem derivada theme-icons com adição de serviço/controller, rotas, provider e views. Host Nginx publica somente o novo helper e dois endpoints adicionais; painel continua restrito pela allowlist administrativa.

Rollback: snapshot privado /opt/agent-center/backups/agent-bootstrap-<timestamp>/ contém arquivos anteriores, host-nginx.conf, compose e rollback.json. Restaurar existentes e remover somente arquivos novos listados; validar nginx -t, recarregar nginx do host e scripts/compose.sh up -d --no-deps web, seguido de php artisan view:clear no web. Não apagar cache global ou dados. Solicitações administrativas expiram naturalmente; Agents já aceitos e dados de tenant devem ser preservados.

Validação: Laravel 40 testes / 489 assertions (Agent API, Operations, Bootstrap e Web UX). Inclui ausência de token antes do aceite, recusa de tenant injection, isolamento cruzado, aceite exclusivo da plataforma, recibo incorreto, repetição, expiração, tenant inválido, enrollment real e heartbeat no banco de teste PostgreSQL. Dois testes do terminal privado confirmam entrega silenciosa do código, prompt fragmentado e preservação de status de erro. Regressão adicional de refresh confirma tenant-context=platform e headers do fragmento. Sintaxe Bash, PHP/Pint e diff whitespace conferidos. Homologação com a máquina real do cliente permanece pendente até ele executar e o operador aceitar.
